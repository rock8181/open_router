## 1. 테스트 전략

본 계획은 OpenRouter 문서 뷰어 웹 서버의 기능, 접근성, 호환성, 성능, 보안, 회귀 테스트를 포함한다. 수동 테스트와 자동화 테스트를 병행하여 커버리지를 극대화한다.

### 1.1 테스트 접근 방식

| 유형 | 범위 | 방법 | 도구 | 담당 |
|------|------|------|------|------|
| 수동 테스트 | 기능, 탐색적 테스트, UI/UX, 접근성 스크린 리더, 모바일 실제 기기 | 테스트 케이스 기반 실행 | Chrome DevTools, NVDA/JAWS/VoiceOver, 실제 모바일 기기 | QA 엔지니어 |
| 자동화 테스트 | 회귀 테스트, API 검증, 브라우저 자동화 | agent-browser 시나리오, 회귀 테스트 케이스 R1~R15 | agent-browser, curl/HTTP 클라이언트 | QA 엔지니어 |
| 접근성 테스트 | WCAG 2.1 AA, 스크린 리더, 키보드 네비게이션, 대비, 터치 타겟 | 수동 + 스크린 리더 | NVDA, JAWS, VoiceOver, axe-core | QA 엔지니어 |
| 성능 테스트 | 페이지 로드, API 응답, 애니메이션, 메모리 누수 | 측정 기반 | Chrome DevTools Performance/Network/Memory, Lighthouse | QA 엔지니어 |
| 호환성 테스트 | 브라우저 × OS × 디바이스 매트릭스 | 수동 | Chrome, Edge, Firefox, Safari (데스크톱/모바일) | QA 엔지니어 |

### 1.2 자동화 테스트 범위 (agent-browser)

자동화 가능한 시나리오는 TESTING.md의 2절과 7절을 따른다. 주요 자동화 대상:

- 앱 오픈 및 `.status` 상태 확인 ("준비")
- 사이드바 폴더 네비게이션 (`#nav-*` 클릭)
- 문서 카드 클릭 → 뷰어 오버레이 오픈 (`#viewerOverlay`)
- 뷰어 닫기 (`#closeViewerBtn`, Escape)
- 검색 기능 (`#searchInput`, `#searchBtn`)
- 새로고침 버튼 (`#refreshBtn`)
- 뷰어 복사 버튼 (`#copyBtn`)
- 문서 수 표시 (`#docCount`)
- API 헬스체크 (`/api/health`)
- 경로 traversal 차단 (`/api/view?root=...&file=../../etc/passwd`)

자동화 불가능 (수동 전용): 스크린 리더 음성 발표, 실제 모바일 터치 제스처, 키보드 포커스 시각적 확인, 스킵 링크 동작, 대비 비율 측정.

### 1.3 테스트 우선순위

| 우선순위 | 정의 | 완료 기준 |
|----------|------|-----------|
| **P0 - Critical** | 치명적 결함. 차단 이슈. 수정 전까지 릴리스 불가 | TC-001 ~ TC-007 모두 통과 (특히 TC-002 문서 카드명 표시 버그 수정 필수) |
| **P1 - High** | 중요 기능. 사용자 경험에 직접 영향 | TC-008 ~ TC-017 모두 통과 |
| **P2 - Medium** | 편의 기능. 일부 제한 가능 | TC-018 ~ TC-023 통과 권장 |

### 1.4 진입/종료 기준

**진입 기준 (Entry Criteria)**
- Express 서버가 `http://localhost:3000`에서 기동됨
- 테스트 데이터 (샘플 문서, 폴더)가 준비됨
- 테스트 브라우저 및 모바일 기기/시뮬레이터 사용 가능

**종료 기준 (Exit Criteria)**
- 모든 P0 테스트 케이스 통과
- P1 테스트 케이스 90% 이상 통과, 잔여 P1은 알려진 이슈로 문서화
- 발견된 모든 중요 버그 수정 및 재테스트 완료
- 회귀 테스트 (R1~R15) 전체 통과

## 4. 버그 추적

### 4.1 버그 보고서 템플릿

모든 버그는 아래 템플릿을 사용하여 기록한다.

```markdown
## 버그 보고서

| 필드 | 내용 |
|------|------|
| **버그 ID** | BUG-XXXX |
| **제목** | [간결한 버그 요약] |
| **테스트 케이스 ID** | TC-XXX (해당 시) |
| **우선순위** | P0 / P1 / P2 |
| **심각도** | Critical / High / Medium / Low |
| **상태** | Open / In Progress / Fixed / Verified / Closed / Reopened |
| **환경** | Chrome 120 / Windows 11, 데스크톱 |
| **재현 단계** | 1. ... 2. ... 3. ... |
| **예상 결과** | ... |
| **실제 결과** | ... |
| **증빙 자료** | 스크린샷, 콘솔 로그, 네트워크 HAR, agent-browser 스냅샷 |
| **발견자** | QA 엔지니어 |
| **발견 일자** | YYYY-MM-DD |
| **수정 버전** | vX.X.X |
| **검증 일자** | YYYY-MM-DD |
| **비고** | ... |
```

### 4.2 버그 생명주기

1. **Open**: QA가 버그 신규 등록
2. **In Progress**: 개발자가 수정 중
3. **Fixed**: 개발자가 수정 완료, QA 검증 대기
4. **Verified**: QA가 재테스트 통과 확인
5. **Closed**: 버그 종결
6. **Reopened**: 수정 후 재발생 또는 미수정 시 재오픈

### 4.3 TC-002 관련 중점 추적 항목

TC-002는 본 프로젝트의 주요 버그 수정 사항이다. 문서 카드명이 빈칸으로 표시되는 문제를 다음과 같이 중점 추적한다.

- **재현 확인**: 앱 오픈 시 그리드 카드의 텍스트 내용과 `aria-label`이 비어있는지 확인
- **원인 조사**: `app.js`의 카드 렌더링 로직, API 응답의 `name` 필드 누락 여부, 템플릿 바인딩 누락
- **수정 검증**: 수정 후 모든 폴더/문서 카드에 실제 이름이 표시되는지 확인
- **회귀 확인**: 수정 후 TC-001, TC-003, TC-004 등 관련 테스트 재실행

| 경로 traversal | `../../../etc/passwd` | HTTP 403, 접근 거부 |
| 존재하지 않는 문서 | `nonexistent.md` | HTTP 404, 파일 없음 오류 |
| 잘못된 루트 | `root=invalid` | HTTP 400, 잘못된 루트 오류 |
| 한글 파일명 | `한글문서.md` | 정상적으로 표시, 인코딩 문제 없음 |
| 특수 문자 태그 | `AI/ML`, `React.js` | 태그 필터링 정상 동작 |
